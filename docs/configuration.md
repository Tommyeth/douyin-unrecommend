# 工作模式与通知配置

- **仅提醒 `notify`**：发现新增推荐就发送消息，保留推荐。至少配置一个通知渠道。
- **自动取消 `auto_cancel`**：处理已有及新增推荐，跳过保留名单。可以不配置通知；取消后重新读取完整列表，确认移除才记为成功。
- **手动清理**：预览本批作品 → 确认取消 → 复核结果。每批默认最多 5 条。

首次完整检查把已有推荐视为首次发现；仍在列表中的同一条推荐不会重复提醒，完整扫描确认消失后又出现则重新提醒。这是定时检查，不能判断误触，也不能监听手机点击瞬间；「自动取消」指检查到后处理。间隔、调度延迟、失败退避和单批上限都会影响处理时间。

## 在面板配置通知

进入「消息通知」→「添加渠道」，填写名称与类型对应的字段，点击「加入待保存配置」后再「保存通知设置」。可配置最多 8 个渠道，不需要重新部署。

- Bark：服务地址通常为 `https://api.day.app/push`，另填 App 中的 Device Key。
- 企业微信机器人：填完整的群机器人 Webhook 地址（包含 `key`）。
- Webhook：填 HTTPS 地址，可选 Bearer Token；请求正文是事件 JSON。
- SMTP：填写主机、用户名、授权码/密码、发件人与收件人，使用隐式 TLS 465。

保存后点「测试已保存渠道」检查实际送达。测试按钮使用已保存配置，编辑框中尚未加入或保存的内容不会被发送。

面板配置优先于 `NOTIFICATIONS_JSON`；移除全部渠道并保存可以关闭通知。「使用部署配置」删除面板覆盖，重新使用环境变量。移除渠道会丢弃该渠道的未发送消息。密码、Device Key、完整通知 URL 与 Token 加密保存，读取接口不回显；编辑时留空保留原值，Webhook 可单独移除 Token。

## 登录失效会不会通知

**配置至少一个渠道后，任务检测到登录失效会发送「抖音登录已失效」，提示打开面板重新扫码。** 未配置渠道不会发送；无法在抖音使会话失效的瞬间获知，需等待下一次检查。

已知登录失效后，定时任务停止访问抖音，避免反复请求。首次通知如果投递失败，仍会在后续调度中退避重试，不受暂停读取的影响。重新扫码成功后恢复日常任务。其他任务错误也会通知，同类错误按小时去重；通知平台和网络故障仍可能影响送达，面板会显示待发送数量。

## 参数

| 参数                    | 默认值   | 说明                                   |
| ----------------------- | -------- | -------------------------------------- |
| `MODE`                  | `notify` | `notify` / `auto_cancel`，面板设置优先 |
| `POLL_INTERVAL_SECONDS` | `3600`   | 面板设置优先；范围见各部署说明         |
| `MAX_PAGES`             | `10`     | 每轮读取页数上限                       |
| `MAX_ACTIONS`           | `5`      | 每轮/每批取消数上限                    |
| `ACTION_DELAY_MS`       | `3000`   | 取消后到复核前的等待                   |
| `PAGE_TIMEOUT_MS`       | `20000`  | 页面/接口等待上限                      |
| `IGNORE_IDS`            | 空       | 逗号分隔的保留作品 ID，不提醒、不取消  |
| `NOTIFICATIONS_JSON`    | `[]`     | 部署默认渠道；面板保存的配置优先       |
| `PUBLIC_ORIGIN`         | 空       | Docker HTTPS 反向代理的来源地址        |

| 通知渠道       | 支持方式                                                  |
| -------------- | --------------------------------------------------------- |
| Bark           | 官方或自建服务，JSON POST                                 |
| 企业微信机器人 | 群机器人 Webhook，检查业务错误码                          |
| Webhook        | JSON POST，可附 Bearer token，携带事件 ID                 |
| SMTP           | 隐式 TLS 465、AUTH LOGIN、UTF-8 MIME；不支持 STARTTLS 587 |

事件有 `new_recommendation`、`cancelled`、`error`、`test`。通知失败后退避重试，只有配置的渠道会收到消息；外部投递在极端断线时可能重复，Webhook 可用 `Idempotency-Key` 去重。建议配置后先点击「测试已保存渠道」。

Vercel / Cloudflare 混合版直接请求 `familiar/recommend/cancel`，Docker 由浏览器页面发起；只允许取消本轮推荐列表实际读到的作品，并检查接口成功和完整列表已移除，不操作「喜欢」。账号不匹配、读取失败或需重新登录时停止相关操作。

Vercel / Docker 默认仅提醒、3600 秒；Cloudflare 混合版默认自动取消、900 秒。已保存的面板设置优先于环境变量。一个部署绑定一个账号；更换平台不会自动暂停原平台的调度。

Vercel / Cloudflare 混合版在登录时保存头像和昵称，「核对账号」仅确认身份和确认时间；Docker 会在浏览器任务中更新资料。

Bark 已通过项目通知函数的真实手机投递测试；企业微信、Webhook 和 SMTP 有协议测试，使用自己的地址和凭证部署后仍需点击「测试通知」确认实际送达。企业微信需在支持群机器人的企业微信群内创建机器人，个人微信与外部联系人群不等同于这个功能。配置字段见 [完整示例](../examples/notifications.json)。
