# Vercel 混合版验收记录

日期：2026-11-16。目标为 Chromium 仅处理登录和人工验证，后续由 Vercel Node.js 函数纯协议读取、取消与完整复核。

## 当前状态

代码已部署，`/healthz` 返回 `vercel-hybrid`。本地 87 项测试及 GitHub CI（含 Docker noVNC 集成测试、原生 Node 模块加载和 Worker 回归）全部通过。原生产设置保持每 900 秒自动取消、通知渠道为空。调度为 Schedules `*/15 * * * *`、状态 active。

本轮发现旧登录态已失效，一次性转换未通过身份确认，原状态保留。修复截图中断后，真实 Vercel 登录窗口持续到正常扫码时限，最终因未完成扫码而超时，未再提前报 `login_image`。真实重新扫码、纯协议读取和取消尚待完成，**暂不宣称本轮已验收通过**。旧版浏览器执行的历史记录见 [原验收记录](vercel-verification.md)，Cloudflare 的通过结果也不代替 Vercel 出口实测。

## 已验证的实现

- 旧会话只能显式转换，定时任务不会为它自动启动浏览器。
- 扫码或转换后先关闭 Chromium，再由 Node `fetch` 核对账号与完整列表；成功落盘后才报告登录成功。
- 协议失败保留加密候选会话，可独立重试；账号不一致不能覆盖已绑定会话。
- 使用模拟接口验证新的函数调用可恢复状态、执行取消和重读，浏览器启动次数不增加。
- 已知登录失效会停止后续调度；失败记录与最近调度结果保留在面板接口中。
- Node 原生模块检查覆盖 JSON 导入属性，避免开发加载器掩盖生产启动错误。
- 登录截图有恢复路径，连续抓图失败不提前结束窗口；截图恢复和取消均有回归测试。

测试使用真实本地 Chromium 和模拟抖音响应。真实账号验收结果将在完成后补充；模拟测试不代表生产网络已通过。

## 验收步骤

1. 在 Vercel Chromium 完成扫码和人工验证，关闭浏览器后纯协议验证通过。
2. 另一次函数调用完整读取推荐；记录浏览器启动次数。
3. 用授权测试推荐验证取消返回成功，并完整重读确认消失。
4. 再次调用和实际 Schedules 调度恢复会话，浏览器启动次数不增加。
5. 核对仍为自动取消、900 秒、无通知渠道。

登录 Cookie、签名、短信内容与账号标识不写入公开记录。返回 [部署说明](vercel.md)。
