## 短信输入前会话退出与画面延迟修复

实际复现：Private Blob 较大响应经过压缩后，GET 返回弱 ETag，直接用于 `ifMatch` 条件写会失败。小状态的一次操作验证无法覆盖此问题。现使用 `Accept-Encoding: identity` 读取强 ETag，且拒绝用弱 ETag 写入；保留条件写与并发保护。

验证期间不再根据暂存 Cookie 自动跳转页面，避免打断短信输入。需要跳转时由用户点击「验证完成，检查登录」。会话从启动开始显示独立倒计时，约 4 分钟后结束；图片改为 JPEG 并缩短操作检查间隔，增加「输入并确认」。后续真实短信验证已通过，见上表。

生产域名复验：真实 Chromium 连续 12 次独立按键操作均收到执行确认，加密状态达到 1189 字节后仍返回强 ETag 并成功条件写。首次画面约 12.6 秒、JPEG 约 25 KB；首次按键约 5.9 秒，后续按键约 1.6–3.4 秒；主动取消约 2.7 秒完成，最终 busy=false。这里测试的是人工操作转发及持久化，不是账号验证答案。

输入体验修正：画面点击后读取实际输入焦点（包括嵌套页面），成功时明确提示并聚焦本地输入栏；远端没有可编辑焦点时拒绝发送文本。截图保留光标。新增嵌套页面聚焦/失焦测试，管理页贯通测试同时验证本地输入栏自动聚焦；真实短信验证已完成。

读取阶段诊断定位到：推荐接口已返回 HTTP 200，但 `page.goto` 等待 DOMContentLoaded 被慢资源阻塞。读取与取消复核现从导航 commit 后开始等待账号和推荐接口；新增慢资源下读取、协议取消、完整复核的回归测试。受鉴权保护的状态 API 保存阶段、请求/响应数量与错误摘要，不包含请求签名或 Cookie。

最终真实账号结果：扫码、短信验证、跨函数恢复登录态、读取与自动取消全部通过。本次通知 channels 为空，sent=0、failed=0 不能解释为真实通知送达成功；Bark、企微、Webhook、SMTP 的实际送达仍需部署者配置并测试。
