## 后续实测方法

用户确认 Safari 可以正常登录，并未实际看到滑块。对先前失败的同一会话进行一次本机协议轮询也返回 `7`；该探测发生在原会话期限之后，不能用于判定新会话的本机成功率，也不能把失败直接归因于 Cloudflare 出口。尚无证据证明需要滑块验证码。

1. 使用自己的实例生成二维码，在抖音 App 中扫描并确认，管理页应显示登录态已保存。
2. 在个人账号上准备一条明确用于测试的推荐，点击「预览本批作品」，核对返回的作品。
3. 确认取消本批，要求取消接口成功且完整推荐列表中已不存在该作品；在抖音 App 中核对。
4. 再次读取列表；重新部署 Worker 后再次读取，验证 D1 恢复会话。
5. 配置自己的通知渠道，测试通知并验证两种模式。通知发送未经真实收件渠道验收时，只记录协议模拟测试结果。

正常日志仅输出错误分类，不打印完整上游 URL、Cookie、二维码 token、签名和原始登录响应。公共问题报告中也请避免上传这些数据。
