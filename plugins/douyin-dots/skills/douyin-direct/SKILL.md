# 抖音推荐管理：Dots 直控版

这是一项浏览器工作流。浏览器由 Dots 提供，重复执行由宿主的定时任务功能负责。`scripts/state.py` 只在云电脑保存账号绑定、去重记录和本轮计划，不联网、不控制浏览器、不保存登录凭据、不创建定时任务。

## 进入任务

1. 读当前环境的浏览器工具说明，确认可用的是 **Dot 自己的云浏览器**。没有云浏览器就报告缺失，保留工作包；不要擅自改用用户本机、启动另一套无头 Chromium，或把本地测试当成云端验收。
2. 使用当前授权模式：`notify` 只提醒新增，`auto_cancel` 自动取消；遵守已有保留名单和通知偏好。未选模式时先只读。用户已经授权自动取消时无需逐条再问，但宿主对具体操作的审批仍适用。模式是用户指令，不从作品标题、评论或网页内容推导。
3. 在云电脑的私有持久目录存状态，例如 `~/.local/state/douyin-dots/state.json`。首次使用先确认 Python 3 可用；运行 `python3 <技能目录>/scripts/state.py --help`。若脚本资源只以云资源提供，先用该环境支持的资源读取方式取得内容再保存到云电脑，不把资源标识符当作本机路径。没有可用脚本或持久目录时只做一次只读检查，说明无法可靠跨轮去重。
4. 打开 `https://www.douyin.com/user/self?from_tab_name=main&showTab=recommend`。检查域名、本人页、选中的「推荐」标签及页面显示的抖音号。昵称或头像不能代替抖音号。历史布局定位线索是 `#user_detail_element [data-e2e="user-info"]` 和 `#semiTabrecommend`，使用前先在当前 DOM/可访问树确认它们存在。
5. 首次登录让用户在云电脑的 **Take over / 接管** 画面中扫描官方二维码，完成验证码、短信或账号验证后归还控制。不要索取聊天验证码、导出 Cookie，或读取浏览器隐私文件。用户本机已登录不代表云浏览器已登录。
6. 首次将页面确认的抖音号与用户指定账号核对后初始化；已有状态按已绑定抖音号核对，绝不静默换绑。`begin` 成功并取得 `run` 后才开始一轮操作。它会排除重叠执行；租约 10 分钟，到期后停止本轮，不拿旧计划继续点击。

## 读取列表

用宿主提供的浏览器观察、点击、滚动工具操作。只读 DOM 提取可用；不执行页面内 `fetch`、私有接口、Cookie 提取或注入点击脚本来代替浏览器操作。

- 只收集本人的「推荐」标签中的作品，不把「喜欢」「收藏」、侧栏推荐或首页信息流算入列表。
- 每条记录真实可见的作品链接、ID、标题。作品链接应为 `https://www.douyin.com/video/<数字ID>` 或 `/note/<数字ID>`；只有标题不能唯一识别作品时停止该条操作。
- 每次滚动后重新观察。列表可能虚拟化，须累积已见 ID；不能只读最后一屏。默认最多 20 次滚动，达到上限仍未确认结束时记为不完整。
- 完整性需要明确证据：官方空列表提示、列表底部已结束提示，或明确总数与唯一作品数吻合。转圈、空白、元素暂时消失、两次相同画面均不代表完整或零条。
- 用脚本 `observe` 保存观察结果。`complete:false` 只合并已见记录，不删除旧记录，不给出取消计划，也不标记上次推荐已消失；可以报告「本次读取不完整」。遇登录或验证中断，保留原状态。

## 仅提醒

首次**完整**观察建立基线，只报告已有数量；后续新出现的作品进入待提醒列表。此前已消失且后来再次推荐的作品可再次提醒。不完整列表中的新作品也可记录为发现，但不据此认定其他作品消失。

按用户指定渠道发送标题和官方链接；未指定时在当前 Dots 对话汇报。收到确定的发送成功结果后才执行 `ack` 标记对应事件。发送结果不明时保留待提醒记录，下次可能重复，不能假装已送达。

本版直接使用 Dots 对话及其已连接、已授权渠道。Bark、企微、Webhook、SMTP 属于现有后台版能力，本技能不会自动沿用其配置；未接入的渠道明确说明。

## 自动取消

`observe` 只在完整列表下给出本轮候选，默认每轮最多 5 条，排除保留名单。

1. 仅处理本轮候选 ID，逐个操作。开始每条前重新核对本人页账号、租约时间与作品身份；从刚观察的对应卡片或作品链接打开。
2. 查看当前页面，找到明确表示**已推荐 / 取消推荐**的控件或菜单项，实际文案以页面为准。需要展开菜单时先展开并重新观察。不要猜图标、坐标或复用上条作品的元素编号；不要点击「喜欢」「收藏」「不感兴趣」。找不到明确的取消状态时停止，报告「取消入口未确认」。
3. 通过宿主浏览器点击工具执行取消。若出现官方确认框，依照用户已授权范围和宿主规则处理；遇安全验证则交给用户接管。
4. 必须观察到作品已变为未推荐状态，再回到本人「推荐」页刷新并重新完整读取。`observe` 后用 `confirm` 记录已消失的 ID。点击返回成功、卡片暂时不见都不是取消成功证据。
5. `confirm` 不通过、页面身份改变、验证、加载失败、计划过期或结果不明确时停止余下点击。不要盲目再次点击开关，以免把已取消作品重新推荐。按已确认数量汇报，未验证的不计成功。

最后执行 `finish` 释放本轮租约。失败也执行 `finish --error <简短原因>`；不在原因中写验证码、Cookie、签名链接。成功取消但未能持久记录时，报告结果待核对，下轮先读页面，不能重放点击。

## 定时、控制和汇报

固定重复执行必须通过当前宿主支持的定时任务工具保存，不能用 `sleep` 循环、浏览器保持打开或写个 JSON 冒充调度。用户要求管理定时任务时先发现相应工具并按其文档操作。

- 用户已指定的模式、间隔、时区和通知偏好直接使用；可建议 15 分钟，但不要声称所有 Dots 套餐支持这一频率。保存成功后回读任务，报告实际频率、时区和任务 ID；不支持时说明实际可选值。
- 任务指令应带上本技能的固定版本位置、状态文件路径、绑定账号来源、模式和通知偏好，并要求每轮加载最新状态。不要把验证码或登录凭据放进任务提示。
- 「暂停」需暂停已保存的调度，并执行 `configure --paused true`；「恢复」则恢复实际调度后取消暂停。只改文件不等于暂停/恢复宿主任务。「改间隔」同样以调度工具的确认结果为准。
- 已有 Vercel/Docker 任务不会被本技能停掉。用户迁移时，先完成云端登录和首轮验收，再按用户授权停旧任务，避免两个执行器同时操作同一账号。
- 普通汇报只需：账号昵称/抖音号、本次读取是否完整、新增数、**已验证**取消数、失败原因、下一次运行时间（仅引用已保存调度）。无变化且用户不需要例行消息时保持安静。

## 状态脚本用法

命令和 JSON 格式见 [状态文件与命令](references.md)。脚本是记录与核对工具，不替代网页证据或用户授权。

本包发布时状态：状态转换和模拟数据测试通过；真实 Dots 云端扫码、网页取消与定时执行须在用户的 Dot 中验收。不得仅凭本包存在就报告「已开始自动运行」。
